# 编译期代码优化计划

起点：`main` 的 `90dc825`（准备期间从 `c901b87` 快进，包含反射修复 `187f498`）；工作分支：`codex/compiler-optimization`。
目标负载：脚本循环、函数调用和对象操作。JIT 不在本轮范围内。

## 本轮约定（2026-10-19）

用户已调整旧运行时路线图的约束：

- 步数预算用于终止失控脚本，不要求保留旧执行器的每一个扣费点、余额和预算失败位置。允许编译优化减少计算量，允许运行时减少检查点；不同引擎按同一工作量标准计费，最终验证数值差距。
- 逻辑调用深度上限可以取消，不作为内联和其他编译优化的约束。调用 trace、原生栈资源保护、VM workspace 和所有权清理仍需各自明确处理。
- 本轮从主分支继续，先做编译期优化；反射生命周期修复由既有工作负责，须核对其合入状态。

这些约定替代 `docs/runtime-performance-roadmap/PLAN.md` 中逐点计步和保留逻辑调用深度限制的优化要求。旧阶段的测试记录仍是历史事实，不改写为本轮结果。

## 验收标准

1. 充足预算下，优化前后返回值、类型、宿主副作用、浮点行为、错误类别及源位置、对象复制/析构顺序一致；不能以删掉运行时错误的方式优化。
2. 同一优化级别下，源码与其导出的 AST 再编译得到相同 ABD；debug 开关不改变指令。优化级别不同允许 ABD 不同，初期不改 exec v10。
3. 预算以优化后的程序为计量对象，允许 O0/O1 消耗不同。树/VM 对同一产物的成功运行先使用现有一致标准；后续稀疏检查阶段的初始容差定为 `abs(tree-vm) <= max(32, 5% * max(tree,vm))`，以覆盖所有负载组的计量测试审查并定稿。
4. 每条循环回边、递归调用环及重入执行链必须有预算检查，余额在重入时共享。长直线区段以最多 64 个现有逻辑工作单位为批量校验上限。原生内建仍沿用既有计费单位与容量限制，不在此轮增加按字符串字节或容器元素计费的另一套规则；可执行脚本的内建路径继续共享预算。预算耗尽位置可不同，必要原生清理必须完成。C04 的 VM 标量快路径已实现该上限，其他路径仍逐点检查。阻塞的宿主函数需要宿主自己的超时/取消机制。
5. 取消默认逻辑深度上限时同步迁移 C++、JNI、CLI 行为、快照说明和测试。最终采用 0 关闭、正数显式启用的可选上限，保留宿主现有接口；不把原生递归路径改成无限制。快照不保存执行限制，因此不修改其格式版本。
6. 各优化独立可关闭；记录产物大小、编译耗时、执行工作量及 Release 耗时，不以指令数直接冒充时间收益。

## 分阶段执行

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| C01 | 引入 O0/O1 和独立优化 pass；类型检查、降级后折叠整数/布尔常量表达式，debug 编号前完成 | 常量边界、溢出/除零保留、求值副作用、AST/ABD 往返、两引擎测试通过；报告代码量与步数变化 |
| C02 | 类型化编译 IR、基本块和显式副作用/所有权信息；复用现有 ExecShape 遍历作为过渡 | 所有 opcode 可表示；与 O0 输出对照；函数调用、别名、可能抛错、分配和析构均有标记 |
| C03 | 标量常量传播、复制传播、冗余转换和死临时值消除 | 数据流跨分支汇合正确；调用/宿主/别名写入会使相关事实失效；有实测收益 |
| C04 | 沿用统一工作量计费，批量检查；取消默认逻辑调用深度限制 | 空死循环、互递归、默认工厂、析构、回调重入均可终止；满足跨引擎误差与检查间隔要求；API/快照迁移完成 |
| C05 | 受控小函数内联、泛型专用化、可证明的静态虚调用消解 | 保留参数快照、语义上的调用错误信息及清理；专用版本有上限；不依赖未验证的槽类型 |
| C06 | 循环不变量外提及对象逃逸分析 | 不提前触发零次循环的错误，不跨越宿主/别名修改；对象身份、复制和析构可观察行为不变 |
| C07 | 全量验证、Release 对照与默认策略决策 | 普通全量及适用 sanitizer、JNI/插件/安装验证；收益覆盖循环/调用/对象，列出回退与代码体积 |

C01 默认保持 O0，显式 `-O1` 启用，便于建立独立对照；后续达到行为和性能门槛后再切换默认。不要求先完成整套 Java 编译器重写才开始取得收益。

## 实施边界

- C02 的类型化 IR 至少记录值类型/未知类型、符号与槽身份、基本块及边、源位置，以及读写、可能抛错、分配、脚本重入和清理效果。可读 JSON 是输入/输出边界；首批从现有已检查的 exec 适配，逐步替换生产端，不把删除整个旧前端作为先决条件。
- C03 先分析标量局部量。分支汇合取共同成立的事实，循环通过不动点计算；未知宿主调用、反射及别名写入保守地使相关槽事实失效。只有已求值的无别名临时值可直接传播。死结果不代表操作可删：可能抛错、调用和清理仍须保留。
- C04 统一工作单位与检查位置：单位描述优化后执行的工作，检查可以按块累计；循环和重入不能重置余额。保留每个实际工作点的计费；VM 批量校验最多 64 个计费点，错误时余额与位置仍精确。按数据大小重新定义原生内建工作单位不属于本轮执行方案。逻辑深度上限、实际原生栈保护和错误栈展示是三个独立问题。
- C05 的首批内联候选是小型标量函数，拒绝未证明的重入、对象生命周期和递归。去掉调用深度上限不等于允许改变 `getDepth` 或错误 trace；需要保留逻辑调用/作用域信息，或保守拒绝相关内联。本轮只对固定 int/bool 上下文的泛型 identity 在调用点展开，不创建函数版本或缓存；未来若扩展版本缓存，必须区分完整绑定上下文和代码版本并限制版本数量。
- C06 的外提只处理已证明不变且不会引入提前报错的操作，特别覆盖零次循环和宿主修改全局的情况。对象逃逸分析必须先说明对象身份、按值复制及析构的可观察性，不能仅凭结果未使用删除对象。
