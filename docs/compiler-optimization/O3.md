# O3：exec v11 开发阶段

`-O3` 与 Java `Compiler.Optimization.AGGRESSIVE` 启用开发阶段的激进优化。根记录的 exec 版本暂时仍为 10；新产物可能使用 opcode 54–60 和私有入口，只供 exec v11 分支的运行库使用。`-O0`、`-O1`、`-O2` 的阶段集合保持不变，`ADVANCED` 明确列出原来的十个阶段，不随新增枚举自动扩大。

设计约束与完整目标见 [exec v11 设计](../exec-v11-roadmap/DESIGN.md)。本文区分当前已实现的安全子集与后续范围。

## 内联与局部槽

O3 统一通过 `seq` 展开直线标量函数。候选函数接收并返回 int/bool，可以有标量声明、赋值、其他封闭标量调用，最后以一个 return 结束；含 if/while 或多个 return、递归、隐藏上下文及对象生命周期的函数保持调用。展开链最多四层，候选正文最多 128 个节点，最多 16 个参数。缺少可恢复源码位置或含无显式类型的局部时保留调用。调用者也必须是封闭标量区域；含对象生命周期、宿主观察或其他开放调用时保留调用，清理区域不展开。普通调用失败会在调用者清理前发布错误栈，成功调用会清除已发布错误栈，两者均可能被析构或宿主探针观察，只有最终内联帧记录不足以替代这些边界。不能证明参数实际运行时类型时也保留调用。

需要快照的实参在原调用位置从左到右各求值一次，写入调用者根块预先声明的槽。未被被调者赋值的参数可以用字面量直接替换；局部变量实参在后续实参不写入该槽时，也可直接复用。编译器从右向左累计实参中的槽写入，嵌套 seq 的写入同样计入；封闭标量调用不能访问调用者 cell，因此复杂实参本身不再强制其他变量创建快照。被赋值的参数、后续可能改写的变量和复杂表达式仍保留必要快照，不能跳过未使用但可能抛错或有副作用的实参。只接收一个参数且同型原样返回的函数直接保留实参表达式，不生成额外序列或槽，并保留其调用者位置和一次求值。

被调者的局部仍提升为根声明，初始化留在原位置的序列内。因此调用可以处于二元运算、惰性分支和循环条件中，每次执行的条件与次数均保留。实参类型必须来自封闭标量区域的运行时类型证明；非直返函数继续保留内联调试链。

内联后只在 seq 内传播已生成临时槽的常量与简单变量复制，复用现有受检查常量折叠；除零、溢出和非法移位仍保留运行时运算及源码位置。写入使依赖该槽的复制事实失效，惰性分支独立处理且不向外传播事实。未再使用且右值为已证明标量叶子的临时赋值可以删除，未引用的根声明随之删除并重新编号；可能抛错或有副作用的赋值仍执行。即使语句清空也保留 seq，供嵌套内联调试记录定位调用点。

`seq` 不引入作用域。其语句列表只允许局部 SET/MOVE 与调用，递归拒绝声明、块、return、if/while、break/continue 和 cleanup。设计第 6.1 节提出的复杂控制流被调者尚未开放，须先解决它与第 4.1 节严格序列的契约差异。

最后的槽压缩仅处理封闭标量函数：参数槽固定，同类型局部可复用已经完全退出的词法块的槽；同时存活的父子块和根部快照不合并。函数不超过 4,096 节点与 256 个槽，内联增长不超过原节点数加 `max(128, 原节点数/2)`，并校验真实 ABD 嵌套；超限回退。各 O3 阶段共用代价审核，检查节点、槽、ABD 深度，以及保守估算的 VM/MIR 指令与恢复单元。增长超过 4,096 个原生操作或 8,192 个恢复单元时回退；新私有克隆超限则回退整个阶段以免留下悬空调用。这些估算不能代替真实 lowering 和性能门槛验收。

## 专用化

常量实参为 int/bool 且被调者和调用者都是封闭标量区域时，编译器按“原函数 ID + 完整常量位置/值向量”建立私有克隆。克隆保留签名与实参求值，在入口设置已知参数后重新进行控制流、公共表达式、死代码和数据流优化。正文至少缩小 25% 才保留；每个原函数最多四个版本，每模块最多 64 个。ID 在原 namespace 中从 `0xffff` 向下分配，跳过定义和 extern 已占用的 ID。原公开函数保留，克隆使用 `entry-kind=2`。

泛型上下文键包含完整绑定结构、常量位置和值及具体化模式，递归替换全部 ref，并折叠固定 context ABI 与 int/bool 默认值。编译器保存源码类型参数到参数、局部槽和返回值的映射；对封闭 int/bool 绑定精确改写 ABI 与局部声明、删除隐藏参数，并仅在类型证明充分时移除冗余检查。删除检查时保留子节点已有位置，缺失时继承检查的位置，使后续内联仍可恢复调用点。只有所有实参都已证明符合新签名时才重定向调用；未知宿主结果、显式 any、对象与递归区域保留检查。具体化版本还可因满足直线内联条件而被保留，原公开泛型入口始终保留。其他固定上下文仅做保守绑定和折叠，保留隐藏签名与检查并要求正文缩小至少 25%。不会只按 int/bool identity 合并不同上下文。

## 对象与整数运算

字段标量化目前处理封闭函数中的 int/bool 字段、直线且不会抛错的字段初始化、空析构和空方法表；自动指针与字面量对象的字段读取、写入和只返回字段的方法改用独立标量槽，字面量复制具有独立字段组。原分配、对象复制、构造调用和清理仍执行，以保留可观察的 block ID、堆长度与空闲区间；本阶段不承诺消除分配。任何回调、地址逃逸、虚调用、非空析构或未证明安全的构造/方法使整个函数回退。一般析构体的正常与错误出口展开仍待完成。替换成功后重新运行所选 O2 阶段；保留的生命周期节点仍限制标量 JIT 资格。

字段缓存只复用已经成功检查为标量的读取。当前缓存点为新局部定义中的显式转换或类型检查，不能凭名义字段类型缓存任意 `mem_get`。别名写入、开放调用、循环、cleanup/drop/delete 等可能改变存储或重入脚本的操作使缓存失效。传递封闭的标量函数调用可以保留缓存，但实参必须由字面量、此前成功缓存的标量局部或这些值组成的标量表达式证明安全；仅有名义字段类型或标量返回类型不足以放宽失效。去虚化在新鲜对象工厂、可见方法表与无失效使用均可证明时生成直接调用；其他本编译单元可见方法槽的唯一目标生成 `guard_method`、直接调用和原虚调用的选择；接收者若无法安全重复求值则保留原调用。守卫失败保留原虚调用的错误路径。

区间分析证明 int32 add/minus/multiply 不溢出后，发射对应无检查节点；左移还需证明移位数为 0–31 且结果不溢出。没有证明的操作保持原 opcode。循环事实沿用现有 CFG 与扩宽。源码自增本来降为赋值和 add，满足证明时复用无检查 add；专用 increment opcode 已有编解码与运行时支持，但编译器暂不直接发射。

## 调试与关闭选项

O3 的有无 `-g` 使用相同执行节点。编译器内部始终保存 O3 的位置和内联来源，不带 `-g` 时输出前移除这些元数据与文件表。内联记录恢复被调函数的名称和出错位置，并通过调用点位置连接外层帧；参数求值仍属于调用者，失败时不添加尚未进入的被调者帧。私有克隆沿用原函数显示名和源码位置。

旧关闭选项继续生效；`--no-inline` 同时关闭序列内联。AGGRESSIVE 的初始阶段集合排除两个旧内联器，关闭全部新 O3 阶段也不会重新启用它们。新增选项分别为 `--no-sequence-inline`、`--no-slot-compaction`、`--no-specialization`、`--no-context-specialization`、`--no-scalar-replacement`、`--no-field-cache`、`--no-devirtualization` 和 `--no-unchecked-arithmetic`，也可通过 Java 显式阶段集合选择。开关的存在不表示本路线图中所有目标形态均已实现。


## 局部清理与字段缓存后续（2026-10-23）

本轮生产改动仅在编译器：实参后缀写入分析、seq 内常量/简单复制传播及无用临时槽删除，以及封闭标量调用的字段缓存保留。新分析沿用原有类型、封闭调用和增长上限，不扩大运行时或执行格式。分支合并的字段事实、一般临时槽活跃性分配及复杂控制流内联仍未开放。

424 Java、20/20 CTest 和统一 `--offline --jit --quick` 通过。统一入口在独立输出目录复用 native 构建缓存，包含全部前置跨语言与真实 JNI、101 个四档定向 / 1,432 次观察 / 3,288 项预算检查、460 语料 / 5,520 观察、默认 O0 树/VM 与两个 stress 模式各 55,451 次比较及 LLVM stress 后端对齐 1,379/1,379。现有 ASan/UBSan 运行库另通过 460 语料 / 7,360 观察、8 堆案例 / 384 比较及新增九例 144 观察 / 900 预算检查；普通七模式九例为 198 / 1,350。没有重复此前两套完整驱动。

O0/O1/O2 每档 470 份输入与上轮完全相同，O3 467/470 相同；变化的三个案例补全 O3 全预算 22 对进程与七模式各 22 次严格重放。策略模式对这些低调用次数案例不触发原生编译，新混合实参热循环另确认所有适用模式的实际原生进入。200 个生命周期样本仍全部字节一致，保留原 18,111 个预算点证据。冻结编译器与集成编译器的 127 个类内容相同。

## 上一轮参数快照验证

2026-10-23 暂停恢复阶段的完整普通与 sanitizer 驱动均通过，原始结果继续保留。本轮只修改编译器的参数快照选择，在独立报告目录运行统一入口的 `--offline --jit --quick`，复用已有 native 构建缓存；未重复完整七模式普通驱动或完整 sanitizer 驱动。

## Release 性能（2026-10-23，参数快照优化后）

使用 `tools/bench_compiler_o2.py`，在 Apple M2 Pro、macOS arm64、LLVM 18.1.8 上，O2/O3 使用相同 Release 运行库，19 负载各执行 7 轮 × 5 批，参数为 4,096。532 个计时进程均核对结果，编译耗时、ABD 大小、槽数、实际原生进入次数和加载库摘要保存在 [性能记录](O3-performance.json)。`off` 表示 VM，`on:3+llvm` 表示 LLVM 配置；对象与虚调用帧仍可能在 VM 执行。

O3/O2 热态耗时的几何均值为 VM 0.874、LLVM 配置 0.530，分别减少约 12.6% 与 47.0%。总体回退门槛通过，未新增原生规模拒绝。拒绝检查按每个负载的汇总计数进行，不能据此推断每个函数的资格。六类目标在两个模式中 6/12 达标，整体状态仍为 `targets-unmet`。
