## 实施阶段

1. `-O2` / Java `Optimization.ADVANCED`、显式 O1 阶段集合、标量效果与 CFG 分析。
2. 跨分支传播、公共表达式复用、不可达分支和无副作用死赋值消除。
3. 有界标量内联，保留参数求值顺序和次数以及被内联运算的源码位置。
4. 整数范围证明驱动的安全循环不变量外提。
5. O0/O1 产物兼容、O2 双引擎/JIT 差分、性能与发行验收。

O0 仍为默认，O1 的阶段与顺序保持不变；O2 不选择后端、不改变 exec v10、
VM/JIT ABI、预算或原生编译阈值。跨优化级别允许错误调用栈缩短和资源耗尽位置变化，
保持普通错误类别与源码位置、getDepth、副作用和对象生命周期。
同一产物的 VM/JIT 观察仍严格比较。

新增分析只处理有界的封闭标量区域；未知宿主/反射/别名、对象清理及递归保守处理。
函数最多分析 4,096 个 exec 节点及 256 个参数/局部槽；超过时保留原有优化结果。
该限制控制编译器分析内存，与 LLVM 的 MIR 规模阈值无关。

## 当前实现边界

- O1 固定为原有四个阶段。O2 新增 `FLOW_PROPAGATION`、`CONTROL_FLOW`、`COMMON_SUBEXPRESSIONS`、`DEAD_CODE`、`SCALAR_INLINING`、`RANGE_LOOP_MOTION`，可由 Java 阶段集合独立选择。`--no-propagation` 同时关闭两种传播，其他关闭选项遵循语言说明。
- CFG、支配关系、活跃性和区间在编译器内部计算，采用确定性工作列表及循环区间扩宽。当前增强阶段要求整个函数及可达调用链为封闭标量代码；含对象、宿主、反射、未知调用或递归的函数保留 O1 结果。它不会把分析结论或新标记写入 ABD。
- 公共表达式复用使用局部槽中的已成功计算结果；覆盖直线代码、由它支配的条件分支及循环内未被改写的值。循环条件和循环体只沿用结果槽及全部操作数都不在循环写集合中的缓存，分支汇合保守清空；局部作用域结果不向外泄露。不会在首次执行前猜测有风险运算的结果。
- 死代码消除保留可能出错的计算和仍被赋值语句需要的声明。无引用、不会报错的标量初始化可删除；现阶段不压缩原有局部槽编号和 `local-count`，不会删除原函数及其 ID。
- 内联只处理完整初始化值、赋值右侧或返回值。候选最多 64 个 exec 节点、8 个参数，按冻结候选运行两轮，最多展开两层。实参一次求值并存入新槽，原函数局部槽重新编号。惰性表达式、循环条件及嵌套在其他运算中的调用不展开。
- 每个调用方新增槽最多 128；节点增长最多 `max(64, 原节点数 / 4)`。循环阶段复用已有槽，每函数最多移动 64 个初始化，不增加槽或节点。原节点与槽数按 O1 处理后的函数计量。超过限制或 ABD 嵌套限制时保留原代码。
- 循环外提使用循环头区间及整个循环的写集合，包括嵌套循环。只移动循环体直属、全函数仅一次写入、所有使用均在该循环内且被原声明支配的标量初始化；声明复用原槽。初始化必须在零次循环路径也确定安全、类型匹配，所有操作数不被循环修改。可依次移动相互依赖的只读初始化；跨迭代修改、作用域复用和可能报错的运算保留原位。不估算 MIR，也不改变 JIT 阈值。不展开循环、不缓存对象字段、不重排浮点表达式。

## 验收入口

统一普通与 sanitizer 验证包含 O2 定向差分和完整 VM 语料的 O0/O1/O2 对比。
`tests/compiler_o2_end_to_end.py` 可用 `--baseline-classpath` 检查旧 O0/O1 产物字节一致，
用 `--baseline-host` 验证旧 v10 运行库，用 `--jit-modes` 对同一 O2 产物严格重放。
模拟器可加 `--flow-batch-size 8`，将生成的 48 个控制流函数分为六批执行，
保留全部函数和独立参考结果；默认仍在一个样例中验证全部 48 个函数。
`tests/compiler_optimization_corpus.py --o2 --jit-modes ...` 对完整语料做同样的 JIT 对比；
编译模式必须记录实际进入次数，不能全部回退 VM 后算通过。
统一入口在含 JIT 的工作树中自动重放其可用模式，保留 JIT 分支已有的
`--jit` 构建、VM 预算差分和后端对齐流程。

性能入口 `tools/bench_compiler_o2.py --classpath ... --native ... --work build/o2-performance --modes off,on:3+llvm`
使用 Release 宿主、7 轮轮换顺序、每轮 5 批测量，并校验结果。
报告包含每轮编译耗时（包括 JVM 启动及文件写入）、ABD 大小、局部槽数、
冷启动与热态耗时，以及完整 JIT 会话统计。超过 5% 的热态回退列入 `regressions`，
需要独立复测；O2 新增原生规模拒绝直接导致验证失败。
测量时不得同时运行其他构建或测试，模拟器结果不作为硬件性能证据。

## 性能门槛促成的收紧

初始循环外提候选在 `range_loop` 上 VM 耗时比为 0.801，LLVM 为 1.232；
独立 7 × 5 复测分别为 0.807 / 1.275。随后提高新建临时槽的成本门槛，
但 `range_division` 仍为 0.671 / 1.225。两次收紧前的测量均不满足交付门槛。
因此最终只移动已有只读局部变量的初始化，复用原槽，不新增循环临时槽。
原有两个负载保留为回归组，新增 `range_local` 验证实际发生的外提。

失败及复测证据保留在 `build/o2-performance-final/report.json`、
`build/o2-performance-repeat-range/report.json` 和
`build/o2-candidate3-loop-performance/report.json`，不以新的结果覆盖它们。
最终候选三组循环的独立 7 × 5 定向测量通过，`range_local` 的 VM / LLVM
耗时比分别为 0.575 / 0.532；完整 15 组测量另见下文。

## 完整性能结果

Linux x86_64 / AMD EPYC 9V74（KVM，5 个可见 vCPU、4 核配额、32 GiB 内存），
GCC 14.2 Release、LLVM 18.1.8、JDK 21.0.12.1+1。运行库固定为 `93b5dd0`，
编译器类内容对应 `a9d1e3e`，测量时分支为 `b259460`。没有并行构建或测试。
15 组负载，`n=4096`，7 轮轮换执行顺序，每轮 5 批；每批目标 0.25 秒，
每个计时进程独立启动并校验结果。LLVM 使用 `on:3+llvm`，VM 使用 `off`。

0.5 秒后，VM / LLVM 分别为 0.999 / 1.011，未复现。保留首轮异常值及独立复测，
没有覆盖或删除原结果。只有 `repeated_expression`、`scalar_call`、`range_local`
三组的 O1/O2 产物不同；其余 12 组逐字节相同，测得的差异不归为编译优化收益。
这也限制了此虚拟机上小幅变化的解释，不能据此宣告 O2 全面加速。

三组实际变换的 VM 耗时分别降低约 9%、15%、43%，LLVM 约 5%、67%、46%。
标量内联的代价也明确保留：该样例 ABD 从 1,074 增至 1,260 字节，局部槽从 4 增至 6。
所有符合条件的样例均确实进入编译代码，没有新增 `too large for native code` 拒绝；
本次固定样例未发现可复现的超过 5% 热态回退。对象组保持原产物，不承诺加速。

编译时间包含 JVM 启动及 I/O；冷启动字段为宿主 `cold_to_first_invoke` 阶段。
原始首轮与独立复测报告为 `build/o2-performance-candidate4/report.json` 和
`build/o2-performance-candidate4-repeat/report.json`，索引保留它们的 SHA-256。
