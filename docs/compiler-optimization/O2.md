# O2：兼容 exec v10 的编译优化

实施基线：main `1e0926d`。独立分支：`codex/compiler-o2`。
JIT 对接分支：`claude/runtime-performance-handoff-5mdt6h`；首次核对 `073a1d1`，运行时整合由 JIT 工作维护。

## 实施阶段

1. `-O2` / Java `Optimization.ADVANCED`、显式 O1 阶段集合、标量效果与 CFG 分析。
2. 跨分支传播、公共表达式复用、不可达分支和无副作用死赋值消除。
3. 有界标量内联，保留参数求值顺序和次数以及被内联运算的源码位置。
4. 整数范围证明驱动的安全循环不变量外提。
5. O0/O1 产物兼容、O2 双引擎/JIT 差分、性能与发行验收。

O0 仍为默认，O1 的阶段与顺序保持不变；O2 不选择后端、不改变 exec v10、
VM/JIT ABI、预算或原生编译阈值。跨优化级别允许错误调用栈缩短和资源耗尽位置变化，
保持普通错误类别与源码位置、getDepth、副作用和对象生命周期。
同一产物的 VM/JIT 观察仍严格比较。

新增分析只处理有界的封闭标量区域；未知宿主/反射/别名、对象清理及递归保守处理。
函数最多分析 4,096 个 exec 节点及 256 个参数/局部槽；超过时保留原有优化结果。
该限制控制编译器分析内存，与 LLVM 的 MIR 规模阈值无关。

## 验证记录

接口及分析基础：30 项 exec 相关 Java 定向测试通过，包括原有 O1 回归、
等级/关闭选项、效果边界、循环收敛、分支汇合和整数区间。
这是阶段验证，不代表 O2 最终交付验收。
